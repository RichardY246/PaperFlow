# PaperFlow 迭代要求

## 迭代范围

- 【P0】本轮仅更新 iOS 版本及其相关文档，暂不更新安卓和 Web。
- 【P0】将字体统一、真实推荐、在线文献、API 配置与额度控制、工程结构整理纳入本轮迭代。

## 字体与视觉

- 【P0】App 内所有文字统一使用衬线体，覆盖中英文标题、正文、标签、按钮、导航、弹窗、输入框、提示、时间和 Token 数字。
- 【P0】中文采用宋体类衬线字体，英文采用配套衬线字体；统一字号、字重和行距规则，兼容系统大字。
- 【P0】AI 内容、译文和文本阅读模式使用同一套衬线字体；原始 PDF 保留原文排版，另提供衬线体文本阅读模式。

## 研究兴趣与标签

- 【P0】面向科研研究生与交叉学科研究者，支持设计学、AI、交互等方向的兴趣组合。
- 【P0】在个人资料和兴趣设置中增加“添加自定义兴趣”，支持输入、自建、多选、改名、删除、置顶和排序。
- 【P0】预设标签使用实底，自定义标签使用虚线边框；保持标签可点击状态清晰。
- 【P0】预设标签和自定义标签均可删除；删除仅影响本人的标签列表、筛选和推荐，不修改其他用户的数据。
- 【P0】预设标签不支持改名；自定义兴趣标签仅本人可见和管理。
- 【P0】首页筛选区分“预设标签”和“我的自定义标签”，两区均可折叠。
- 【P0】自定义标签与预设标签使用相同的筛选和推荐逻辑；新增或修改兴趣后更新推荐。
- 【P0】本地保存标签、多选状态和筛选条件，重新打开后恢复。
- 【P1】支持排除标签和不感兴趣方向，允许同时设置关注与排除条件。
- 【建议】合并重复标签，处理空白、大小写和常见中英文别名；删除标签时同步清理失效筛选条件。

## 首页与推荐

- 【P0】增加下拉刷新和明确的刷新反馈；刷新时获取新内容并更新推荐顺序。
- 【P0】点击底部“首页”按钮也触发刷新：从其他页面点击时返回首页并刷新，已在首页时点击则回到顶部并刷新。
- 【P0】实现实际参与排序的推荐算法，以首次设置的兴趣、自定义标签和后续阅读偏好共同决定推荐结果。
- 【P0】首次使用时按所选兴趣从网络召回文献；没有兴趣或历史时，展示近期多领域文献。
- 【P0】根据已阅读文献的主题、关键词、摘要和研究方向，推荐相近文献；每次刷新重新计算推荐排序。
- 【P0】结合有效阅读时长、已读、收藏、点赞和跟踪更新偏好；降低误点和短暂停留的影响。
- 【P0】筛选、排除标签和“不感兴趣”优先约束推荐，删除兴趣后同步调整推荐权重。
- 【P0】采用“兴趣召回、内容相似排序、负反馈过滤、去重及少量探索”的推荐流程，保留部分新方向内容。
- 【P0】AI 文献完成标题、正文、封面文案及概览等必要内容的处理后，才进入首页信息流；已有完整缓存可直接展示。
- 【P0】首次进入、下拉刷新、点击“首页”、切换筛选和加载更多，均只展示已处理完成的 AI 内容，不展示待处理文案、生成提示词或要求用户进入详情后再生成的卡片。
- 【P0】刷新期间保留现有内容，仅显示统一的刷新进度；某篇生成失败时跳过该篇，保留已完成内容，不用待处理卡片补位。
- 【P0】保留向下加载更多，区分刷新、加载中、暂无新内容、来源受限和网络失败。
- 【P0】读过的文章不因进入详情而持续置顶，避免同一批内容反复出现在首页顶部。
- 【P0】筛选条件应用后实时更新信息流；恢复筛选时同步恢复标签状态。
- 【建议】按 DOI、arXiv 编号和论文版本去重，避免刷新或切换来源后重复展示。
- 【建议】增加“不感兴趣”和“为什么推荐”，允许用户调整推荐方向。
- 【建议】仅在主动刷新或修改筛选时重排已有内容；加载更多时追加内容，保持当前阅读位置。

## 在线文献与数据来源

- 【P0】所有文献均从网络文献服务检索或获取，移除安装包内的本地演示 PDF 和预置文献注入逻辑。
- 【P0】首页推荐、统一搜索、原文阅读和 AI 处理共用在线文献数据，不使用固定的本地论文列表模拟持续推荐。
- 【P0】保留 arXiv、OpenAlex、Crossref 等在线来源，文献记录保留真实标题、作者、年份、来源地址和 DOI 或 arXiv 编号。
- 【P0】原文按需联网获取；本地只保留网络获取后的缓存和用户主动下载的内容，提供缓存清理入口。
- 【P0】没有开放 PDF、需要机构登录或下载失败时，提供对应官网入口，并保留已获取的文献信息。
- 【P0】无网络时显示已缓存的真实内容；无可用缓存时显示统一的网络提示，不补入本地演示论文。
- 【建议】升级时按 DOI 或 arXiv 编号关联旧收藏、笔记和阅读记录，替换文献来源时保留用户数据。

## 文献与笔记封面

- 【P0】自动从论文 PDF 提取 Figure 或关键图表，作为文献信息流封面。
- 【P0】封面优先级统一为：本人明确指定或上传的图片、自动提取的论文插图、纯色书本兜底卡片。
- 【P0】支持选择论文首页或其他原文页面作为封面。
- 【P0】封面以图片为主，顶部使用半透明标题遮罩，底部简要显示关键词或年份，减少对图表的遮挡。
- 【P0】在原文阅读页提供插图截取和“设为封面”，操作后预览卡片效果，无需先保存到系统相册。
- 【P0】图片自动适配卡片比例，支持调整裁切位置，预览与首页最终效果保持一致。
- 【P0】自动取图失败时切换到手动截取、上传或兜底封面，不阻断阅读。
- 【P1】增加提亮、去除 PDF 黑边和清晰度优化，保留原图并允许恢复。
- 【P1】提供两至三套轻量封面模板，覆盖“图＋标题”“图＋关键词”和研究结论卡片。
- 【P1】支持可选的 AI 生成封面，明确标为示意图，避免将生成图片展示为论文原始图表。
- 【P1】在详情页标注“图片来自论文原文，仅供学习交流”，并保留原论文、图号和页码信息。
- 【建议】优先采用可解释研究方法或结论的图表；裁切时避免切掉坐标轴、图例和关键标注，支持点开查看完整原图。

## 文献概览与 AI 阅读助手

- 【P0】所有文献与用户笔记详情页统一按“图片或多图 → 跟踪区 → 标题与正文 → 原文及关联资料 → 评论”的顺序排列。
- 【P0】跟踪区紧接图片下方，按作者、期刊、主题展示可点击的信息与跟踪按钮；没有对应信息时不显示空行。
- 【P0】取消 PaperFlow AI 的跟踪入口，不将其作为可跟踪作者、用户或推荐对象；保留必要的 AI 生成标识。
- 【P0】清理已有的 PaperFlow AI 跟踪记录，不影响真实作者、期刊、主题、帖子和文献的跟踪状态。
- 【P0】在文献内容页增加可逐页翻阅的概览卡片，分别呈现研究问题、研究方法、关键图表、主要结论和局限。
- 【P0】概览卡片放在跟踪区之后的正文区域，不打乱详情页从图片到跟踪区再到正文的顺序。
- 【P0】概览卡片使用短句和必要配图，显示当前页及总页数，支持快速进入原文。
- 【P0】区分内容页概览与 AI 助手：概览用于快速了解论文，助手用于具体提问、概念解释和证据查找。
- 【P0】AI 助手先给简短结论，再按需展开支持证据、补充说明和原文定位，减少一次性大段输出。
- 【P0】生成内容注明依据摘要、部分正文或全文；资料不足时明确提示，不凭标题补全研究结论。
- 【建议】每张结论卡片和助手回答提供可点击的证据入口，打开对应原文页并突出相关段落或图表。
- 【建议】缓存已有概览与回答，避免进入助手页自动重复生成；重新生成时保留旧内容直到新结果成功。
- 【建议】标题可以吸引人，但不得编造实验数字、研究结论或比较结果；夸张表达在正文开头明确澄清。

## API 配置与交互

- 【P0】首次打开 App 的引导流程中增加 API 配置页，提供“配置个人 API”和“先体验演示额度”两种选择。
- 【P0】演示服务使用项目方此前提供的智谱 API，默认模型设置为 `glm-5.2`，替换旧的默认演示模型配置。
- 【P0】增加智谱、DeepSeek 和其他兼容接口的配置预设，支持多份配置的保存、命名、切换、测试和删除。
- 【P0】服务地址、模型和密钥统一管理；模型列表允许手动输入，支持平台默认值与高级配置展开。
- 【P0】在首次引导、“我的 → 设置”、AI 助手、额度提醒和调用失败提示中提供 API 配置入口，均进入同一配置流程。
- 【P0】API 设置采用适合手机的选择列表、分步表单或底部弹窗，减少单屏字段，适配键盘与安全区域。
- 【P0】密钥支持粘贴、隐藏和临时查看；保存时校验必填项、HTTPS 地址和模型名称，展示清晰的保存与连接状态。
- 【P0】先配置、后测试、再启用；测试失败保留已填写内容，不覆盖仍可使用的旧配置。
- 【P0】个人密钥保存在本机钥匙串；课堂演示密钥首次设置在演示手机钥匙串中，不写入源码、安装包、文档或 Git。
- 【P0】课堂版本由 iPhone 直接调用模型，手机独立联网运行，不依赖 Mac 代理；本地额度仅用于课堂演示。
- 【P0】文献库密钥与大模型密钥分别管理；切换平台时只使用对应密钥，不静默回退到其他收费配置。
- 【建议】切换配置时处理旧请求和生成队列，避免请求发送到错误平台；缓存保留实际服务商、模型和语言。

## Token 用量与演示额度

- 【P0】区分项目演示额度与个人 API 用量，界面始终能够识别当前使用的服务、模型和额度来源。
- 【P0】在 AI 助手的生成结果和问答结果附近简要显示本次 Token 用量；展开后查看输入、输出和总 Token。
- 【P0】在 API 设置或用量页显示累计用量、当日用量、最近调用记录，以及演示额度的已用量和剩余量。
- 【P0】Token 数量以接口返回的实际用量为准；接口未提供时显示“用量未提供”或明确标记估算，不展示虚构的精确数字。
- 【P0】项目演示 Token 上限由统一配置设置，并在体验入口明确显示；免费论文体验上限为 3 篇。
- 【P0】达到演示 Token 上限或成功展示第 3 篇 AI 翻译论文时，任一条件成立即停止后续演示 API 调用，并提示配置个人 API 或模拟充值。
- 【P0】免费篇数按成功处理且实际展示的不同论文累计；同一篇重复查看或读取缓存不重复计篇，失败不计成功篇数。
- 【P0】明确每篇体验论文的翻译范围，区分摘要、概览、部分正文和全文，不将摘要翻译描述为全文翻译。
- 【P0】额度核算覆盖演示密钥下的解读、翻译、问答、重新生成和连接测试；服务商实际计费的失败请求仍计入 Token 用量。
- 【P0】演示额度由本机钥匙串保存；关闭、重开、刷新或重置普通演示数据不会重置额度，多个请求共用同一额度。
- 【P0】请求前预留预算，并限制输出 Token 和生成队列；剩余篇数或 Token 不足时停止预加载，避免后台继续消耗额度。
- 【P0】触及上限时保留已经处理完成的内容和第 3 篇论文的阅读入口；刷新不展示待处理卡片，也不阻断已有收藏与原文阅读。
- 【P0】配置个人 API 并验证成功后，后续调用切换到个人额度，保留原有内容、阅读记录和演示用量记录。
- 【P0】提供明确标注“仅演示，不产生真实扣款”的模拟充值页；确认后模拟增加额度，并记录演示交易。
- 【P0】模拟充值不接入真实支付、不索取支付凭证，不将演示金额与服务商账户真实余额混用。
- 【建议】对即将触及额度、请求失败但用量尚未确认等情况显示统一提示，避免误导用户重复点击调用。

## 原文阅读与翻译

- 【P0】优化手机 PDF 阅读，支持适应屏幕宽度、缩放、横屏和页码跳转。
- 【P0】为英文文献增加按段或按页中文翻译入口，保留原文并支持对照阅读。
- 【建议】增加适合手机的文本阅读模式，支持调整字号、行距和背景，同时保留完整 PDF 入口。
- 【建议】译文保留公式、图号、表号和参考文献对应关系；术语可查看原文，翻译不替换原文证据。
- 【建议】保存每篇论文的阅读页码和位置，再次打开时继续阅读。
- 【建议】翻译按需加载并缓存，显示生成进度，支持取消与失败重试。

## 图文发布与社区互动

- 【P0】从当前论文直接截取插图，用作笔记配图或封面，无需额外的本地保存步骤。
- 【P0】截取图片时自动关联论文，保留来源、图号或页码；发布前可预览和调整。
- 【P0】评论区支持选择或截取论文插图后发送图片讨论，支持点开大图。
- 【P0】消息通知预览展示关联笔记的封面图，并可进入对应帖子或讨论。
- 【P0】标签和封面仅允许本人修改；笔记使用他人论文插图时保留来源信息。
- 【建议】删除或更换图片前保留未发布草稿，图片处理失败时不丢失标题、正文和关联资料。

## 阅读历史与个人记录

- 【P0】阅读历史以真实论文标题为主，不使用引流标题替代论文身份。
- 【P0】历史记录保留作者、年份、来源和实际阅读时间，支持返回原文与内容页。
- 【建议】增加按论文标题或作者搜索历史，以及日期筛选、继续阅读和单条删除。
- 【建议】将打开记录、实际阅读时长和手动已读状态分开记录；取消已读时保留访问历史。

## 体验性能与验收

- 【P0】PDF 插图提取、封面处理、翻译和 AI 生成在后台执行，不阻塞页面浏览和翻页。
- 【P0】后台生成仍受当前 API 配置、Token 预算和免费篇数限制；额度不足时暂停任务并引导配置。
- 【P0】扫描版 PDF 或无法识别图片层的文件提供手动框选截取，不要求自动提图必然成功。
- 【P0】核对 iOS 的卡片比例、弹窗、翻页和筛选交互，重点验证 iPhone 真机效果及系统大字显示。
- 【P0】记录新增标签、封面切换、一键取图和筛选使用事件，不记录密钥、密码或论文私人笔记正文。
- 【P0】验收预设与自定义标签删除、标签管理、筛选更新、重新打开恢复、截取插图、设为封面、发布配图和评论发图的完整流程。
- 【P0】验收下拉刷新与点击“首页”刷新；检查所有新展示的 AI 内容均已处理完成，生成失败时不出现待处理卡片。
- 【P0】验收所有内容页的图片、跟踪区和正文顺序，并确认所有页面均无 PaperFlow AI 跟踪入口。
- 【P0】验收首次 API 配置、演示体验、个人配置切换、Token 用量显示、两类额度上限和模拟充值流程。
- 【P0】验收刷新推荐随兴趣及阅读行为变化，推荐去重有效，安装包不再包含演示 PDF。
- 【P0】验收所有 App 文字均使用统一衬线字体，并检查大字、键盘和小屏适配。
- 【建议】为图片处理、网络检索和生成请求增加进度、取消、失败重试与缓存管理。
- 【建议】统一文字层级与按钮样式，兼容系统大字，来源说明保持清晰可读。
