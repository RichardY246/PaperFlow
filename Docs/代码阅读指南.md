# PaperFlow 代码阅读指南

2026-11-16，适用于 iOS 1.8.2。

## 原图比例与余额失败恢复

`PaperCover` 对原图使用自身宽高比，让卡片高度跟随图片；只有 AI 图和占位区保留 4:3。笔记照片裁切规则不变。

`ImageRecoverySelection` 只读取当前缓存索引中的明确余额失败项，排除成功、未知、已计次、已移除论文与手选封面，不会拿历史中的旧失败再次付费。`startBalanceRecovery` 先查原图，再复用串行生图流程；中途换 API、停止或遇错就暂停后续项。首页与设置共用 `ImageBalanceRecoveryView` 显示费用、额度与进度。

## 从入口开始

1. `PaperFlowApp.swift`：注册衬线字体、创建唯一状态中心、恢复本机额度。
2. `ContentView.swift`：启动 Logo、首次引导与主页面切换。
3. `App/RootView.swift`：四页引导、底部导航、路由表和首页。
4. `Features/ReadingViews.swift`：从熟悉的原文和文献详情看按钮如何调用操作。
5. `Data/AppStore.swift`：收藏、跟踪、历史与评论等共同状态。
6. `Models`：了解数据保存哪些字段，再看对应的 `Services`。

## 一次首页刷新

点击底部首页或下拉 → `loadHomeNext` 创建本次请求 ID → 用兴趣和有效阅读构造网络查询 → 各文献服务返回真实记录 → 按 DOI / arXiv 身份合并 → 推荐器使用完整阅读历史排序 → 取得有效原文 → 为未处理论文调用 AI → 校验语言、正文和概览 → 展示卡片。封面由独立管线后台准备，不阻塞正文。

每批最多准备 3 篇。失败跳过，配置或额度错误会停止继续消耗；刷新时保留旧内容。`homeRequestID`、语言与配置版本共同阻止旧请求覆盖新页面；加载更多只追加，阅读计时不会立即把卡片移走。

`recommendedContent` 是首页的最后一道检查：没有已完成解读的论文不展示。统一搜索没有这个限制，因此无密钥时仍能找到真实文献和打开原文。

## 推荐如何学习

兴趣词与论文标题、摘要和主题匹配获得基础分。阅读不足 30 秒不当成有效阅读；之后的阅读时长、手动已读、收藏、点赞和跟踪会改变相似度权重。历史与已读降低重复推荐，排除方向先过滤，再保留少量探索。

算法只用本机记录，不上传用户笔记或阅读行为；可以在卡片长按查看推荐依据。中文常用方向有英文检索别名，自定义方向使用用户填写的文本。

## 一次 AI 调用与额度

`performAI` 固定本次配置、密钥来源和请求 ID。演示模式先从钥匙串载入 `DemoLedger`，预留输入预算与最大输出，预算不足就不发请求。个人模式不借用演示密钥。

请求完成后读取接口返回的 `usage`。成功和实际计费的失败都记录；没有回传用量的已发送请求保留待确认预留。记录显示“未提供”，不会把预算当成精确 Token。后续同一回执不会重复计费。

概览成功只是准备完成，真正交付给页面后才计不同论文数。待交付论文继续占用名额，避免并行请求绕过三篇限制。缓存重复打开不计篇；取消或格式失败不计成功篇数，但实际计费仍保留。

额度和密钥存钥匙串，普通内容存 SQLite、图片存独立文件；重置普通数据不会重置额度。模拟充值修改本地额度并记录无扣款交易，不调用支付服务。

## 数据和卡片为什么更轻

`AppStore` 只持有供页面读取的状态，`StateDatabase` actor 在后台按记录更新 SQLite。论文、解读、评论线程、封面、帖子和译文各有记录；小操作不会重写所有论文。照片使用 Media 散列文件引用，无引用图片在提交后回收。首次升级保留原 JSON 与 pre-sqlite 备份；读取失败停止写入。`flushStorage` 用于后台切换和模拟重启检查。

论文按 ID 索引查询，搜索结果批量合并。词集合、推荐列表与筛选结果缓存；生成正文语言只验证一次，密钥可用状态按配置版本缓存，避免滚动时反复读取钥匙串。推荐批次接收全部历史，搜索按查询相关性独立排序。成功来源通过回调先入库展示，其他来源继续等待。

## 一次封面准备

`CoverPipeline` actor 合并同一论文的请求，提图同时最多一篇；离开卡片会取消无人等待的排队任务，已开始的一篇继续完成缓存。先检查 cover-v3 缓存，再从 arXiv / PMC / 原文 HTML 获取图注关联的原图。SwiftSoup 负责 HTML 解析，不能假设所有论文都有 HTML。

没有网页原图时使用 `FigureExtractor` 和系统 PDFKit 裁切图表。候选带图号、真实来源、可确认的页码、归一化裁切坐标与质检状态；HTML 图片没有对应 PDF 页码时保存为 0（界面显示网页图片），不猜页码。正文混入、过小或识别不可靠的候选不进入封面池；最多三张。

`PaperArtwork` 将结果交给页面；`ImageLoader` 在后台解码缩略图，内存缓存约 40 MB，离屏释放视图中的图片。自动磁盘图片按最近使用目录清理到约 300 MB；手动图片在 Media 中，不参与自动图缓存淘汰。无合格图时采用首页截图，无 PDF 时用标题卡；失败 24 小时内不自动重试，得到新 PDF 或用户点击“重新提取封面”可重试。该按钮不调用 AI，也不改动正文。

## 一次原文获取

`FullTextLinks` 提供已验证链接、开放 PDF 与仓储页面。`PaperFileService.downloadVerified` 逐个尝试；403、HTML 登录页或无效文件不冒充 PDF。HTML 中有 citation_pdf_url 等真实链接时继续下载。只有 PDFKit 确认有效后才缓存。

如果已知版本失败，`FullTextWorkflow.obtainFullText` 可按 DOI 联合查找其他仓储，再合并同一论文的版本。首页仅尝试已知版本，避免一次刷新重复开展全网检索。只有经过验证或本机有已确认缓存时，界面才显示“可直接阅读全文”；来源标为 OA 只代表可能有开放版本。

机构会话交给官方网站和系统浏览器。App 阅读器内学校与出版社使用同一 WK 数据存储，支持跨站认证跳转；它与系统网页、Safari 不自动互通。可从网站下载到“文件”，再在原文页确认导入到当前论文；App 不读取账号密码，也不推测登录成功。

## 一次摘图与评论

后台渲染指定 PDF 页 → 用户框选 → 预览 → 输出 JPEG 与论文页码 → 设为本人封面，或连同论文身份交给发布/评论页面。帖子 `imageCredits` 保留每张摘图的来源，评论 `paperID/page` 可以跳回原文。

`receiveComment` 接受文字或图片，校验来源内容与父评论，再统一保存评论和通知。自己发言不通知自己；别人回复自己的评论会提醒。社区仍是本机演示。

## 容易混淆的写法

| 写法 | 含义 |
| --- | --- |
| `@State` | 页面暂存的输入和加载状态 |
| `@Environment(AppStore.self)` | 读取多页共用状态 |
| `@Observable` | 变化后刷新相关界面 |
| `@MainActor` | 串行处理 UI 状态；等待网络时让出线程 |
| `async/await` | 等待网络或后台结果 |
| `Task.cancel()` | 取消当前任务；已发送请求仍可能由服务商计费 |
| `Codable` | JSON 编解码；新字段用 `decodeIfPresent` 保护旧资料 |
| `var updated = state` | 先汇总多项变化，再一次保存，减少重复写文件 |
| `paper:ID` | 类型和固定身份；引流标题变化不改变收藏与评论身份 |

不要把真实密钥写进代码或测试。测试文件使用假的响应与临时目录，真实文献联网检查不调用付费模型。安装包检查也会确认没有带入测试 PDF。

## 一次封面生成

先由 `PaperArtwork` / `CoverPipeline` 尝试原图。没有可靠候选时，`PaperCover` 才调用 `generateImage`；正文不等待。`ImageCoverWorkflow` 捕获发起时的演示/个人模式与智谱配置，先预占生图次数，将请求写入 SQLite，再调用固定的生图接口。返回 URL 后先保存，成功结算生图次数，再独立下载图片。刷新复用同一任务或结果；下载失败不重新 POST；超时则保留预占，等待用户核对。文字 Token 的流程保持独立。

`Tools/GenerateDemoArt.swift` 是演示笔记插画的可编辑源文件，可用 `swift Tools/GenerateDemoArt.swift PaperFlow/Assets.xcassets` 重建，不需要生图 API。
